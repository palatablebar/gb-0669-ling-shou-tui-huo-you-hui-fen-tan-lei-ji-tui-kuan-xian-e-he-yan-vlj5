# 数据定义

仅处理CNY；所有金额先用Decimal检查精度，再以整数分计算，不进行浮点累加。销售行须有正数量和单价，同订单的整单优惠与运费重复填写但只计算一次。同单SKU唯一，件数上限10000。整单优惠按每件单价最大余额分摊，余数相同时按SKU及件序确定。退货按原件序回收原实付，已退单位不重复使用；全部件数退完才返运费一次。退货按UTC与事件号排序，早于销售或超过数量的退货隔离且不改变已退款累计。

- 空串、`-`、`N/A`、`NULL`、`未知`是缺失哨兵，不作为零。
- 原始批号、事件号均为文本，保留前导零。
- CSV支持UTF-8 BOM和GB18030，必须有完整表头，支持列顺序调整；`channel` 为可选列，取值 `store`/`online`，缺省时按备注识别（含“线上”为线上），仍无法识别默认门店。
- 文件最大2MB、10000条记录；读取时逐记录校验，计算阶段保留受此上限约束的数据。
- 空文件、全空行、仅表头分别标记EMPTY_FILE、BLANK_ONLY、HEADER_ONLY。
- 多余列隔离；非法引号导致整次请求失败，不保存半批。
- 幂等键=输入字节摘要+规则版本+参数；内容完全相同复用批次。
- 复核采用整数版本比较，旧版本返回409。

## 渠道并发与唯一退款结果

- 门店与线上可同时看到同一订单的尾件；资格归属只看**实际退货时间**：按UTC时间排序，同刻按事件号决胜，与同步到达先后无关（`sync_note` 仅作展示）。
- 同步先到但实际退货更晚的渠道收到 `ELIGIBILITY_LOST`，隔离原因写明取得资格的渠道；该渠道页面可见拒绝原因，且本次不冲减任何累计。
- 每次退货展示占用商品（SKU+件序）、退前累计可退、本次可退（含运费）、退后累计可退与运费资格归属；运费只在整单退完时退一次，归属完成最后一件的渠道。
- 渠道事件以事件号为主键落入SQLite持久台账（`ledger_returns`/`ledger_sales`），整单重算在单个事务内完成：同事件号同报文重试回放原结果，绝不二次冲减；同事件号异值或跨渠道冲突返回409 `EVENT_CONFLICT`。
- 台账行记录规则版本；规则升级后旧行 `stale=1`、原批次复核返回409 `RULE_STALE`，`POST /api/channels/recover` 保留全部已确认退货并按新规则重算。
- 非法事件在落库前拒绝，失败不写入半条；已确认退货在任何恢复路径下都不删除。

单字段金额上限为1000000000000元，超过上限返回字段错误。
